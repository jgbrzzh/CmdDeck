# 1.2.1 修复与验收

本版本同时发布此前 1.2.0 的项目工作区、任务诊断、日志、分屏恢复、配置快照等功能，详见 [1.2.0 使用说明](V1.2.md)。

## 审计问题的修复

| 问题 | 当前行为 |
| --- | --- |
| 覆盖导入失败可能丢失配置 | 三种模式先构造完整候选配置并在内存库验证，再通过 SQLite 事务提交；失败保留原配置，提交前保存快照；运行任务时禁止导入 |
| 用户图标没有显示 | 指令卡片显示所选内置图标或自定义文字、Emoji，文字不会作为 HTML 执行 |
| 管理员预设要求整个界面提权 | 必须手动确认，通过 Windows UAC 启动单次工作者；内嵌输出、调整尺寸和停止；拒绝或取消显示中文错误；自动化不提权 |
| 桌面集成缺少实际状态和验收 | 新窗口复用 WebView 数据目录并同步设置；初始化失败显示原因；自启注册失败不会保存成功状态；验证范围见下表 |
| 交互输入绕过预设黑名单 | 默认关闭键盘和粘贴输入，前后端同时拦截；允许 Ctrl+C 和有限协议回应；确认后可开启交互输入；绝对路径白名单覆盖全部执行入口 |

白名单只约束启动程序，不限制解释器脚本和子进程。开启交互输入后，输入不逐条经过预设黑名单。这些机制不是 Windows 沙箱。需要交互的 REPL、登录和安装过程应在设置中明确开启输入。

复制使用系统剪贴板，内容为终端已渲染的纯文本；清屏之后不会复制清屏前的缓冲。管理员工作者使用一次性本机端口和随机令牌，不开启常驻管理员服务。

## 复现命令

在仓库根目录运行，使用独立测试目录，避免修改正式配置：

```powershell
npm ci
npm run build
cargo test --locked --manifest-path src-tauri/Cargo.toml -j 2
$env:CMDDECK_DATA_DIR = Join-Path (Get-Location) 'test-results/repair-runtime'
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9223'
npm run tauri:dev
```

保持程序运行并完成默认示例初始化，另开 PowerShell 连接真实 WebView：

```powershell
npx --yes --package @playwright/cli playwright-cli -s=cmddeck-repair attach --cdp http://127.0.0.1:9223
./scripts/Test-Repair.ps1 -Session cmddeck-repair
npx --yes --package @playwright/cli playwright-cli -s=cmddeck-repair run-code --filename scripts/desktop-repair-smoke.cjs
```

脚本会替换隔离实例配置，仅允许 `test-results` 下的数据目录。出现 `### Error` 不能判为通过。关闭测试应用后构建安装包：

```powershell
Remove-Item Env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS -ErrorAction SilentlyContinue
./scripts/Build.ps1 -Target all
```

普通提交和 PR 仅检查；明确版本标签或手动填写版本号才构建安装包。`v1.2.1` 标签构建成功后自动发布 EXE、MSI、GPL-3.0 许可证和 SHA256。
